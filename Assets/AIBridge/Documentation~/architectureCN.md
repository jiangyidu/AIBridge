# AI Bridge 系统架构设计

AI Bridge 将职责拆分为 **Unity 编辑器 (C# 宿主)** 和 **Python Agent 服务**，两者通过轻量级的本地 HTTP 协议进行双向进程间通信（IPC）。

## 1. 双向 HTTP 进程间通信 (IPC)
C# 编辑器端托管了一个在后台线程中运行的轻量级 HTTP 监听器（`AgentBridge.cs`）。
* **端口分配**：端口号根据当前处于激活状态的 Unity 项目路径的 MD5 哈希值动态计算。这保证了同时打开多个 Unity 项目时端口（范围 8000 至 9999）绝不冲突。
* **端口发现**：Unity 在启动时，将分配好的端口保存至 `AgentController/agent_port.txt`。Python 后端会自动读取该文件以定位当前处于活动状态的编辑器会话。

---

## 2. Python Agent 协调机制
* **`service.py`**：负责管理活动会话，通过 HTTP 响应轮询向 C# UI 流式推送 Agent 的步骤和文本，并将对话记录保存至 `ai_chat_history.json`。
* **`agent_core.py` (ReAct 循环)**：管理 Prompt 模版构建、大模型请求（支持 DeepSeek、Gemini、Claude、Ollama 等）以及工具调用解析。
* **`engine_client.py` & `unity_client.py`**：封装引擎特定的网络请求、超时配置与编译状态检测。

---

## 3. 动态编译工作流
1. **工具调用**：Agent 决策决定编写代码（调用 `compile_temp_method` 或 `compile_script`）。
2. **文件生成**：
   * 临时指令：将静态方法写入 `AITempCommands.cs` 部分类（partial class）。
   * 运行时脚本：在 `Assets/Scripts/AITemp/` 下生成完整的 `MonoBehaviour` 脚本。
3. **编译轮询**：Python 端使用 `check_compile_status` 轮询 Unity 编辑器的编译状态。一旦编辑器成功编译，工具调用即宣告成功。
4. **错误恢复**：如果编译失败，后端会调用 `get_compile_errors` 获取具体编译报错，并执行 `RollbackPendingGeneratedSource` 回滚错误代码，防止污染用户的项目。
