# Contributing to AI Bridge

We welcome contributions to improve **AI Bridge**! Whether you want to fix bugs, add new engine-side APIs, or extend the Python backend to support more LLMs and engines, please follow these guidelines.

---

## 🏗 Coding Standards & Conventions

### C# / Unity Guidelines
- **Unity Compatibility**: Keep compatibility with older Unity versions (specifically down to Unity `2018.4.36f1`). Avoid modern C# features that are not supported in Mono/C# 6 (.NET 4.x runtime).
- **Namespaces**: Place all package editor code inside the `AIBridge.Agent` or `AIBridge.Core` namespaces.
- **Assembly Definition (`asmdef`)**: Make sure to separate Editor and Runtime logic cleanly:
  - Editor scripts belong to `AIBridge.Editor.asmdef`.
  - Runtime scripts belong to `AIBridge.Runtime.asmdef`.
- **Thread Safety**: The HTTP server runs on a background thread. Any interaction with Unity Engine APIs (like scene query, asset search, object modification) MUST be enqueued to the main thread via `AgentBridge.EnqueueMainThread(action)`.

### Python Guidelines
- **Python Compatibility**: Code must run on Python 3.8+.
- **Formatting**: Adhere to PEP 8 standards. Use clear docstrings and comments.
- **File Encodings**: Save all Python source files with `# -*- coding: utf-8 -*-` headers.
- **Dependency Scope**: Keep external dependencies minimal. Currently, we only require the standard library and `requests`.

## 🛠 Extension Points

### 1. Adding Custom Commands
You can write any custom editor commands in `Assets/Editor/AntigravityTasks.cs` or in any of your project scripts:
1. Declare a `public static` method.
2. Mark the method with the `[AgentCommand("Description", category: "CategoryName")]` attribute.
3. Returning a `string` description or status log is highly recommended, as it will be returned to the AI agent.

```csharp
[AgentCommand("Query custom project resources and assets info", category: "Custom")]
public static string QueryResources(string searchPattern)
{
    // C# implementation
    return "Result log details";
}
```

### 2. Supporting New Engines
AI Bridge is designed to be engine-agnostic on the Python side. To add support for other engines (such as AutoCAD, Tekla, Unreal Engine):
1. Create a subclass of `EngineClient` (defined in `AgentController/python_agent/engine_client.py`).
2. Implement the following hook methods:
   - `engine_name`: The display name of the engine.
   - `_resolve_agent_url()`: How to find the engine's HTTP server port.
   - `_tools_schema_fallback_paths()`: Paths to the fallback JSON schemas on disk.
   - `_compile_tool_names()`: Tools that trigger compiler waits.
   - `_normalize_source()`: Language/Syntax normalization if code is generated by the LLM.
3. Register your class in the factory method `create_engine_client` in `AgentController/python_agent/agent_core.py`:

```python
elif engine == "autocad":
    from .autocad_client import AutoCADClient
    return AutoCADClient(**kwargs)
```

## 🚀 Development Workflow

1. **Fork and Clone**: Clone the repository and open the Unity project.
2. **Setup Environment**: Run the **Environment Setup Wizard** inside Unity (`AIBridge -> Environment Setup Wizard`).
3. **Verify Tests / CLI**: Test calling the agent via the CLI controller to ensure the communication stack works:
   ```bash
   python AgentController/unity_agent_controller.py list
   ```
4. **Submit PR**: Open a pull request with a descriptive title, explaining the changes, their rationale, and how you verified them.
